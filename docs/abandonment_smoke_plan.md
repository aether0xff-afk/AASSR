# AASSR 자발적 포기 기능 smoke 계획

## 목적

최종 확정된 strict GridPush 환경에서 Imagination v2가 언제 문제 해결을 포기하려 하는지 관찰하고, 그 판단이 실제로 성공 불가능해진 상태와 일치하는지 확인한다.

이 smoke는 성능 개선 실험이 아니다. 다음 질문만 다룬다.

1. Critic이 포기를 선언할 만큼 낮은 성공 가능성을 언제 출력하는가?
2. 그 상태는 실제로 성공 경로가 사라진 상태인가?
3. 아직 해결 가능한 상태를 너무 일찍 포기하는가?
4. 포기하지 못하고 비정상적으로 오래 남는가?

## 환경

기존 최종 환경인 `BenchmarkGridPushWorld`를 수정하지 않는다.

이 환경은 방문한 칸이 다시 사용 불가능해지고 잘못된 이동이 즉시 실패로 이어지므로, 원래도 에피소드가 task dynamics에 의해 유한하게 끝난다. 따라서 이번 포기는 단순한 시간 초과가 아니라, 아직 행동은 가능하지만 현재 경로에서 성공 가능성이 사라졌다고 에이전트가 판단하는 경우를 대상으로 한다.

## 포기 판단

Imagination v2의 GRU Branch Critic을 별도의 실제 궤적 기억으로 읽는다.

- Critic은 현실에서 실제로 발생한 `(이전 상태, 행동, 다음 상태)`만 순서대로 본다.
- 각 단계에서 현재 궤적이 최종 성공으로 이어질 확률을 출력한다.
- 성공 확률이 임계값 이하인 상태가 연속 `patience`회 나타날 때 포기를 선언한다.
- 최소 관찰 스텝 이전에는 포기하지 않는다.
- Critic이 성공과 실패 경험을 충분히 보아 `critic_ready`가 되기 전에는 포기를 허용하지 않는다.

이번 smoke 조건:

```text
threshold = 0.05, 0.15, 0.30
minimum_steps = 2
patience = 2
```

임계값은 최종 설정으로 채택하기 위한 튜닝이 아니라, 현재 Critic 출력이 어느 범위에서 포기 행동으로 변하는지 확인하기 위한 진단값이다.

## 자기실현 편향 방지

포기 기능은 학습 중 사용하지 않는다.

```text
Imagination v2 정상 학습
→ 학습 완료
→ Policy, Prophecy, Critic 동결
→ 평가에서만 포기 신호 관찰
```

포기한 에피소드를 실패 사례로 Critic에 다시 학습시키지 않는다. 그렇지 않으면 Critic이 포기한 상태는 항상 실패로 기록되어 점점 더 일찍 포기하는 자기실현 순환이 생길 수 있다.

## 두 평가 모드

### 그림자 모드

포기 신호를 기록하지만 실제 에피소드는 계속 진행한다.

이를 통해 포기 선언 뒤 실제로 성공했는지, 자연스럽게 실패했는지 확인한다.

### 실제 포기 모드

동일한 조건에서 포기 신호가 나오면 즉시 에피소드를 종료한다.

그림자 모드와 같은 맵의 결과를 짝지어 다음을 측정한다.

- 포기로 인해 막힌 성공 수
- 실패 에피소드에서 절약한 환경 스텝
- 포기 후에도 성공 경로가 남아 있었는지

## 적절성 판정

Oracle은 학습이나 행동 선택에 사용하지 않는다. 실험 후 포기 상태를 판정하는 용도로만 사용한다.

- `remaining_oracle_steps(state) is None`: 현재 상태에서 성공 경로가 없음 → 적절한 포기
- 남은 Oracle 경로가 존재함 → 조기 포기

이 판정은 에이전트에게 공개되지 않는다.

## smoke 규모

```text
seed = 7
학습 = 300 episodes
학습 맵 = 32
평가 = seen 30 + unseen 30 episodes
모드 = shadow, active
threshold = 3개
```

## 기록 항목

- 포기 선언 스텝
- Critic 성공 확률
- 연속 저확률 횟수
- 환경 phase
- 사용된 칸 수
- bridge/key/door 상태
- 포기 시점의 Oracle 해결 가능 여부
- 남은 Oracle 최단 스텝
- 최종 성공·환경 실패·포기·안전 종료 여부
- 그림자/실제 포기의 짝지은 결과

## 안전 상한

고정 스텝 제한은 사용하지 않는다. 다만 구현 오류나 비종료를 막기 위해 128스텝의 비상 상한을 둔다.

strict GridPush는 정상적으로는 task dynamics에 의해 훨씬 이전에 끝나므로, 상한 도달은 일반 실패가 아니라 `safety_stop`으로 별도 기록한다.

## 해석 제한

이 smoke 하나로 포기 기능의 최종 유효성을 주장하지 않는다. 다음 중 하나를 판별하는 초기 진단이다.

1. Critic이 성공 불가능 상태를 어느 정도 구분한다.
2. Critic이 지나치게 낙관적이라 거의 포기하지 않는다.
3. Critic이 지나치게 비관적이라 해결 가능한 상태를 포기한다.
4. Critic 출력이 0.5 주변에 몰려 포기 판단에 사용할 수 없다.
